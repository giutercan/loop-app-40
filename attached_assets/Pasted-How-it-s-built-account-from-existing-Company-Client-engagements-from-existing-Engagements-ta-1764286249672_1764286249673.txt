How it’s built:
	•	account from existing Company/Client.
	•	engagements from existing Engagements table.
	•	kpis from existing KPI entities.
	•	headlineValue from existing ValueCase / financial engine, summarised.

This is where devs reuse the Document 7 work: don’t re-implement any calculations, just call the existing value case functions and wrap.

Step 3.2 – Lifecycle-aware queries

Add small helpers:
	•	GET /accounts/:id/hub?phase=DELIVER
→ filter engagements and KPIs to those in that lifecycle phase.
	•	GET /engagements/:id/summary
→ returns a compact version used by the role views.

This allows the front end to show “different slices” of the same data by phase.

Step 3.3 – Minimal write APIs for MVP

You don’t have to support every edit path, but you do want:
	•	POST /accounts/:id/issues – create an Issue.
	•	POST /kpis/:id/actuals – log a KPIActual.
	•	PATCH /engagements/:id – update lifecyclePhase.

This lets you actually move things along the loop and see the hub update, rather than being stuck in seed data.

This is the same shape as the PPT, but now drawing real data.

Step 4.2 – Central Hub component: shared value spine

Bind the real data:
	•	Strategy & OKRs → from account.strategySummary, account.okrs.
	•	Issues → from issues.
	•	Initiatives / Workstreams → from engagements.
	•	KPIs → aggregate all KPIs across engagements; you can:
	•	Show a table grouped by engagement.
	•	Highlight KPIs with latest values (using KPIActuals).
	•	Headline value → from headlineValue (promised vs realised).

Add basic phase awareness:
	•	When currentPhase is:
	•	DISCOVER → emphasise issues and early KPIs.
	•	SHAPE → emphasise value summary and engagement list.

All of that is just conditional rendering from the same AccountHub object.
