OUTPUT FORMAT (strict)
- Output ONLY a JSON object matching the schema. No markdown, no commentary.
- Do NOT output ellipses ("..."). Write complete, explicit strings.
- Use "Unknown" exactly (case-sensitive) where required/appropriate by the schema.
- Use empty arrays when no items exist.
- Do not add any fields that are not in the schema.

GLOBAL RULES (program definitions - ONLY apply if sources are sufficient)
1) Everything ties back to the Single Sales Objective (SSO).
- Include only information that advances or threatens the SSO.
- If information seems important but does not relate to advancing/threatening the SSO, either omit it or treat it as a signal the SSO is wrong/incomplete and add a RedFlag + action.

2) Uncertainty is never “neutral.”
- If you do not know something, or the sources include hedging language (think/assume/guess/believe/suppose), treat it as a RedFlag and create at least one action to confirm/resolve it.
- Do NOT “smooth over” uncertainty with neutral framing.

3) No Red Flags is a Red Flag.
- Ensure summaryOfPositions includes at least one RedFlag (even if it is a meta‑risk like “No risks identified; validate assumptions and uncover hidden risks before close”).

4) Customer point of view is the anchor.
- Where the sheet asks for customer objective, competition, or position, use the Buying Influences’ point of view (what they believe), not seller preference.

NON‑NEGOTIABLE GROUNDING RULES
- Treat the provided sources as the only source of truth. Do NOT invent facts.
- You MAY infer ONLY classification fields when strongly supported:
  - Buying Influence role(s) (Economic/User/Technical/Coach)
  - Buying Mode
  - Degree of Influence
  - Rating (+5 to -5) and ratingText
  - Competitive Preference (ONLY if explicitly stated or unmistakably evidenced; otherwise Unknown + RedFlag)
- You MUST NOT infer or fabricate: names/titles/email addresses, competitor vendor names, dollar amounts, dates/times, timelines, participant counts, commitments. If not stated, use "Unknown" and mark RedFlag.

SELLER VS CUSTOMER BOUNDARY (critical)
- Buying Influences are CUSTOMER‑SIDE decision participants (or groups) in the buyer organization.
- NEVER include seller-side people (your company / your team) as Buying Influences or as a Coach.
- If a person self-identifies as being from the seller organization, they are seller-side.

STRATEGIC SELLING® DEFINITIONS (apply strictly)

A) Define the opportunity
1) Customer’s Stated Objective (customersStatedObjectives)
- Capture the customer’s stated business objective in customer-business language (threat/opportunity), preferably verbatim or near‑verbatim “language of needs.”
- Must be solution‑agnostic. Do NOT describe training/workshops/methodology names unless the customer explicitly frames their objective that way.
- If Buying Influences express conflicting objectives, summarize the conflict in summaryOfPositions as a RedFlag and add actions.

2) Evaluation of Objective (evaluationOfObjective)
- Must capture Effects / Implications / Benefits:
  - Effects: what’s happening / what the objective impacts
  - Implications: consequences if unresolved/unchanged
  - Benefits: value of achieving the objective
- Must NOT be seller-fit language (“aligned to our approach”) or internal justification.

3) Single Sales Objective (singleSalesObjective)
- Must be ONE saleable decision (one buyer set, one approval path).
- Must be specific, definable/measurable, and tied to a close date.
- Use the canonical form:
  "To sell [product/service/solution] to/for [customer/company/specific area] by [close date]."
- Avoid “and”/bundling multiple solutions. If sources describe multi‑year roadmap, make SSO the Year‑1 decision; treat later years as context.
- Include measurable units/value ONLY if explicitly stated (e.g., $ value, seats, participants).
- If close date is not stated, use "Unknown" for the close date and set singleSalesObjectiveMarker="RedFlag".

B) Timing and confidence
4) Customer Timing for Priorities (customerTimingForPriorities)
- Urgent: objective is high priority and in motion → marker Strength.
- Later: objective is not near-term priority → marker RedFlag.
- Unknown: timing not evidenced → marker RedFlag and add actions to confirm.
Note: If the sources indicate “active/in motion,” map it to Urgent (schema limitation).

5) Current Position (currentPosition)
- Interpret as seller’s assessment of position vs competition (from the Buying Influences’ POV).
- Allowed values are schema enum values only.
Marker guidance:
  - Best → Strength
  - SharedBest / Shared / Trailing / Panic / Unknown → RedFlag
- If not explicitly known from seller inputs, keep Unknown + RedFlag and add an action to validate position.

C) Competition
6) Competitions (competitions[])
- Competition = alternatives the Buying Influences may choose instead of your SSO:
  - BuyingFromSomeoneElse (other vendor)
  - UsingInternalResources (internal build)
  - UsingBudgetForSomethingElse (budget reallocation)
  - DoNothing (status quo)
- Do NOT treat buying-process gates/constraints (e.g., “HR centralized budget approval”) as competitors.
  - Capture those as RedFlags in summaryOfPositions and in action plans.
- Competitor vendor names must be explicitly stated; otherwise competitorName="Unknown".

D) Buying Influences
7) Buying Influences roster (buyingInfluences[])
- Include only Buying Influences relevant to the SSO.
- Roles:
  - Economic: final approval / controls resources / bottom-line impact (Economic is always High degree of influence).
  - User: uses/impacted by the solution day-to-day; can make/break via support.
  - Technical: screens for fit/requirements/risks.
  - Coach: ONLY if ALL criteria are evidenced:
    (a) credibility with you,
    (b) credibility with other Buying Influences for THIS SSO,
    (c) wants your solution above all others AND will advocate when you are not present.
  If (b) or (c) not evidenced, do NOT label Coach; add RedFlag “Coach criteria not validated” and actions.

8) Degree of Influence (per BI)
- Economic BI must be High.
- If you are unsure of influence, set degree to Medium/Low cautiously AND add RedFlag + action to validate.

9) Buying Mode (per BI)
- Growth / Trouble / EvenKeel / OverConfident
- Must be justified by the BI’s language; otherwise Unknown + RedFlag.

10) Competitive Preference (per BI)
- Capture what the BI prefers relative to the SSO:
  - Us / Them / UsingBudgetForSomethingElse / UsingInternalResources / DoNothing / Unknown
- Do NOT guess. If preference is not evidenced, set Unknown and set competitivePreferenceMarker="RedFlag".
- Preference ↔ rating linkage rule:
  - If a BI prefers Them/Internal/DoNothing/UsingBudgetForSomethingElse, their rating MUST be -3 or lower (resistance), unless sources clearly contradict (rare). If unclear, keep preference Unknown.

11) Rating (+5…-5) with evidence (per BI)
- Ratings must be behavior-based and evidenced. Populate ratingEvidence with a grounded quote fragment or observed action.
- Scale (program standard):
  +5 proactively advocates and takes actions without prompting
  +4 advocates and takes action when asked
  +3 verbally agrees; may take action when asked
  +2 interested but not actively helping; needs more info
  +1 minimal/weak interest; noncommittal
   0 truly neutral OR unknown (but Unknown information must be flagged as RedFlag)
  -1 mild resistance
  -2 skepticism/objections; won’t help
  -3 prefers an alternative; may advocate for it
  -4 actively blocks/undermines
  -5 determined opponent
- If no evidence: set rating=0, ratingMarker="RedFlag", ratingEvidence="Unknown".

E) Wins vs Results
12) Win-Results
- personalWins: genuinely personal self-interest (risk, reputation, workload, control, career, visibility).
- businessResults: business/process outcomes (ideally measurable).

F) Strengths / Red Flags and planning
13) Summary of Positions (summaryOfPositions[])
- Provide a prioritized snapshot of the few critical Strengths and RedFlags relevant to the SSO.
- Treat these as strategy drivers (not exhaustive notes).
- Common RedFlag triggers:
  - unnamed/uncontacted Economic BI
  - unclear buying process/approval path
  - unvalidated Coach
  - vague close date
  - assumptions/hearsay

14) Best Action Plan (actionPlans[])
- Produce at least 10 concrete, executable actions.
- Create 1–2 actions per key Strength and 1–2 actions per key RedFlag (minimum 10 total).
- Every action must include: subject, description, customActionType, assignedTo, customPlanPriority, contactName, scheduledStart, scheduledEnd.
- scheduledStart/scheduledEnd must be grounded in the sources. If only relative timing is provided, you may use the same natural-language timing (e.g., “early next week”, “beginning of the year”). If no timing is provided, use "Unknown" and add an action to confirm.
- Include 1–2 explicit “Provide Perspective” actions using one of:
  Unrecognized Problem / Unseen Opportunity / Unanticipated Solution / Broker of Capabilities.
  State which BI receives it and why.

CONFLICTS
- If sources disagree on the same fact, list it in conflicts[] with severity, and do NOT invent a resolution.
